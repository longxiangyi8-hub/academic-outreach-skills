# Cold Email Writer

把申请者经历与导师公开研究方向进行有依据的匹配，生成可人工审核的英文联系邮件草稿。

## 输入与配置

需要：

- 申请者 CV，通常为 PDF 或 DOCX。
- 包含导师姓名、职位、方向、邮箱和来源链接的 Excel 或 CSV。
- 申请目标与写作偏好：项目类型、入学时间、是否接受 RA 过渡、署名、附件名称和语气。

若个别偏好未提供，使用中性、简洁的学术邮件风格并保留可替换占位符。不要从示例推断申请者姓名、学校、入学季或学位目标。

开始前检查导师记录是否有可用来源。信息不足时可以给出保守草稿并标记复核，但不得补写未验证的论文、项目、招生名额或研究观点。

## 读取申请者背景

从 CV 提取并结构化：教育背景、研究兴趣、科研或工程项目、方法与工具、论文或成果、实习、奖项、语言能力和量化结果。

- 只使用 CV 中明确出现的事实。
- 保留数值、单位、角色和成果归属，不夸大个人贡献。
- 同一经历只提取一次，记录可支持哪些研究方向。
- CV 解析不确定或文本缺失时先标记，不靠猜测补齐。

## 评估匹配度

对每位导师分别比较四类证据：

1. 研究问题或应用领域是否直接重叠。
2. 方法、数据、设备或技术栈是否可迁移。
3. 申请者是否有可证昍的研究成果或深入实践。
4. 导师方向是否来自当前、可核验的官方资料或近期公开成果。

使用以下等级：

- `High`：至少有一项直接研究重叠，并有方法或成果证据支持。
- `Medium`：领域或方法部分重叠，存在清晰的迁移路径，但缺少直接研究经历。
- `Low`：交集有限，主要依赖宽泛兴趣或通用技能。

同时写入一到三句“匹配理由”，引用具体 CV 经历和导师方向。没有证据时降低等级，不为了写出邮件而制造交集。

## 撰写邮件

详细结构、事实边界和可配置风格见 [references/email-guidelines.md](references/email-guidelines.md)。

每封邮件应做到：

- 称呼、项目目标和署名正确。
- 选择一到两段最相关经历，不复述整份 CV。
- 说明具体技术或研究连接，而不是只写“您的研究很有趣”。
- 对导师工作的描述可追溯到名单中的研究方向或已核验来源。
- 不声称读过某篇论文，除非已实际获取并核对论文内容。
- 不虚构招生状态、论文细节、future work、共同兴趣或申请者能力。
- 默认保持简洁，通常约 180 到 280 个英文单词；用户指定其他长度时按要求执行。
- 输出是草稿，不发送、不创建 Gmail 草稿，除非用户另行明确要求并授权。

## 写回表格

按表头定位导师行和目标列，不依赖固定列号或固定导师数量。

- 目标列建议为 `匹配度`、`匹配理由`、`套瓷信` 和 `复核状态`。
- 列不存在时追加到右侧；存在时只更新当前任务明确要求的行。
- 保留原有数据、样式、公式、合并单元格、筛选器及人工进度。
- 同一导师重复出现时先解析是否为跨院系重复，不能确认时标记复核。
- 保存为新文件或可恢复版本，除非用户明确要求覆盖原文件。

## 质量检查

逐行验证：

- 邮件为英文，教授姓氏和署名正确，没有未替换占位符。
- 申请者经历、数字和技术术语与 CV 一致。
- 导师研究描述有来源，未虚构论文或招生信息。
- 匹配等级与理由一致，Low 不被包装成强匹配。
- 相邻邮件不是简单替换姓名的同一模板。
- 没有泄露电话、住址、证件号或无关个人信息。
- 所有目标行都有匹配度、理由、草稿和复核状态。

最后报告 High、Medium、Low 的数量、需要人工复核的行，以及输出文件位置。提醒用户在发送前逐封检查并确认附件。
